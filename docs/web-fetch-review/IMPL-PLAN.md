# web-fetch fidelity & robustness — Implementation Plan

Spec: `ACTION-PLAN.md` (same folder). Supporting evidence: `review-code.md` (static review, file:line), `qa-report.md` (live QA), `research-tools.md`, `research-pi-api.md`. Raw HTML captured from real sites lives in `qa-out/*.raw.txt` and is the fixture source.

Repo: `/Users/hoangta/.pi/agent/extensions/web-fetch` (git, branch `fidelity`). Runtime: Node 22, pi 0.84.3. Deps: @mozilla/readability 0.6.0, turndown 7.2.4, linkedom 0.18.13.

## Global Constraints

- Goals in priority order: (1) no information loss in the markdown, (2) context-lean, (3) minimal/simple code, (4) robust. When in tension, never trade (1) for (2).
- Keep the architecture: `fetch.ts` (HTTP) → `extract.ts` (content-type routing + markdown) → `index.ts` (tool registration, truncation, temp file, TUI). New modules only where the plan names them (`rewrite.ts`, `pdf.ts`).
- Never post-process markdown with regexes that could touch fenced code. All cleanup happens on the DOM before Turndown, or inside Turndown rules.
- Tests: `node:test` via `npx tsx --test tests/*.test.ts` (script `npm test`). Fixture tests are offline (HTML in `tests/fixtures/`). Live tests only in `test.ts` (existing) and only opt-in.
- Do not add dependencies beyond: `@types/turndown` (dev), `typescript` (dev), `unpdf` (Task 5). No jsdom, Defuddle, mdream, cheerio.
- `@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, `typebox` are aliased by pi's loader — never declare them as dependencies; keep them importable via the tsconfig `paths` set up in Task 1.
- Type-check must pass: `npx tsc --noEmit`.
- Errors from `execute` must be thrown (`WebFetchError`) — pi sets `isError` only on throw.
- Output header format (index.ts) stays: title line, `source:` line, optional `author:`, size line, optional `full:` line, `---`, markdown. Additions to the header are specified in Task 6 only.
- Commit after each task with a descriptive message. Do not commit `node_modules`, `.superpowers`.

## Task 4: HTTP robustness (Phase 2.1, 2.2, 2.5, 2.6, 2.7) — fetch.ts

Add `tests/fetch.test.ts` using a local `node:http` server (no network) to cover each item. Items:

1. Request headers: `Accept: text/markdown, text/html;q=0.9, application/json;q=0.8, text/plain;q=0.7, */*;q=0.5`; `Accept-Language: en-US,en;q=0.9`; keep the Chrome `User-Agent`; remove any `sec-ch-ua` / `Sec-Fetch-*` headers if present. `text/markdown` responses pass through as `mode: "text"` (check extract.ts `TEXT_TYPE_PATTERN` already matches `text/markdown`; do not change extract.ts otherwise).
2. Retry once with plain UA `pi-web-fetch/1.0 (+https://pi.dev)` when the response status is 401, 403, 429, or 503. If the retry also fails, throw the error from the retry. Test: server returns 403 for Chrome UA and 200 for the plain UA.
3. Error quality: (a) network errors include `error.cause.code` and message (`ENOTFOUND`, `ECONNREFUSED`, `CERT_HAS_EXPIRED` …) plus the URL; (b) timeout during **body read** and cancellation during body read map to `WebFetchError("Timed out after 30s: <url>")` / `WebFetchError("Cancelled: <url>")` — wrap `readBoundedBody` too; (c) non-2xx: include status text and the first 300 chars of the body **after** stripping `<script>`, `<style>` blocks and tags and collapsing whitespace; (d) echoed URLs in messages truncated to 200 chars; (e) when the body is cut at `MAX_BODY_BYTES`, set `truncatedAtBytes: true` on `FetchedPage` (new field; index.ts renders it in Task 6); (f) 204/empty body → `WebFetchError("Empty response (204/no body): <url>")`; (g) `javascript:`, `data:`, `file:` URLs → `Unsupported protocol` message (not "Not a valid URL").
4. Content-type gate before download: if the response `Content-Type` is a known-binary family (`image/*`, `video/*`, `audio/*`, `font/*`, `application/zip`, `application/gzip`, `application/x-tar`, `application/octet-stream` when the URL path ends in a binary extension, `application/pdf` **unless** the caller passes `allowPdf` — add `fetchPage(url, signal, {allowPdf?: boolean})` and have PDFs return `body` as a `Uint8Array` field `bytesBody` instead of a decoded string when allowed; Task 5 consumes it) — cancel the body and throw with type and `Content-Length` before reading. Otherwise accept all `text/*`, `*/*+xml`, `*/*+json`, `application/json`, `application/xml`, `application/javascript`, `application/x-yaml`, `application/toml`, and for unknown types sniff the first 1 KB: if it contains NUL bytes or > 10% bytes outside printable/whitespace ranges, throw as binary. Update `extract.ts` `TEXT_TYPE_PATTERN` only as needed to accept `text/*` universally (review H4).
5. URL normalization: do NOT upgrade bare `host:port` (or `localhost`, `127.0.0.1`, `[::1]`, `*.local`) to https — use `http://` for those; keep https for everything else. Stop stripping `ref`, `source`, `si` from query strings (keep `utm_*`, `fbclid`, `gclid`, `mc_*`, `_hs*`, `igshid`, `ref_src`); NOTE the tracking-param regex lives in `extract.ts` — edit only that constant there.
6. Minor: remove the double-copy of chunks in `readBoundedBody` (concat `Uint8Array`s directly); on error paths read at most 64 KB of body.

Run `npm test` and `npm run typecheck`. Commit: `fix(fetch): markdown content negotiation, UA retry, precise errors, binary gate, localhost http`.
